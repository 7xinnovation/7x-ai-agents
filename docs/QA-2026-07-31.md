# QA guide — 2026-07-31 feedback round

How to test every item from the NXN and EPGL feedback exports on the live app.
Written so each item can be checked independently — no need to run them in order.

**Environment**

| | |
|---|---|
| App | <https://7xagents.7x-lab.com> |
| NXN agent | <https://7xagents.7x-lab.com/embed/nxn-dialog> |
| EPGL agent | <https://7xagents.7x-lab.com/embed/epgl-dialog> |
| Floating widget (as a customer sees it) | <https://7xagents.7x-lab.com/demo?agent=nxn-dialog> |
| Admin console | <https://7xagents.7x-lab.com/admin> |

**Two query params you will use a lot**

- `?locale=ar` — start the session in Arabic, e.g. `/embed/nxn-dialog?locale=ar`
- `?mock=1` — simulates a UAE PASS sign-in **and** simulates the Emirates Post
  operations that need a live EP session, so signed-in journeys complete without a
  real account. Combine them: `/embed/nxn-dialog?locale=ar&mock=1`

**PO Box numbers on staging are reserved test numbers.** Emirates Post staging
publishes no real box availability, so when the availability service returns
nothing the assistant is given a reserved set of test box numbers instead. They
behave like real choices — pick one and the journey continues, and *Refresh* shows
a different set — and they are deterministic, so the same branch always offers the
same numbers when you re-run a scenario. This applies to staging only: it is gated
on the agent's environment and disappears the moment an agent is switched to
production. If a tester asks whether the numbers are live inventory, the answer is
no, this is a test environment.

**Before you start:** click **New chat** (the ⟳ icon in the header) between tests.
Sessions are resumed from `localStorage`, so a stale conversation is the most
common reason a test "doesn't reproduce".

**Reading the results.** Each item below has a **Do**, an **Expect** (pass) and a
**Fail looks like**. Where an item is *Blocked* or *Partial*, the expected result
is the honest behaviour, not the original ask — the reason is stated.

## A. The four items you re-opened

### FB-1430 — Key delivery fee must be disclosed before selection *(NXN)*
> *"Delivery Fee still is not disclosed before final payment."*

**Do**
1. `/embed/nxn-dialog?mock=1` → "I want to rent a personal PO Box"
2. Work through bundle → emirate → branch → box number → duration.
3. When you reach the **key delivery** step, read the two options.
4. Choose **Deliver to address**, continue to the pre-payment summary, then pay.

**Expect**
- The delivery choice itself shows the fee, e.g. *"Deliver to address (AED 25 courier fee)"*, and the other option reads *"Collect from branch (free)"* — **before** you pick.
- The pre-payment summary lists the courier fee as its own line.
- The **Pay now** card total = bundle price **+ 25**.
- Pick *Collect from branch* instead and the total has **no** 25 added.

**Fail looks like** the fee first appearing at payment, or the payment total
matching the bundle price while delivery was chosen.

**Why it should hold now:** the fee is no longer just wording — the journey
declares it as a `surcharge`, and the server adds it to the charged amount. Even
if the assistant forgets to mention it, the amount charged is still correct.

### FB-1439 — Date format must be DD-MM-YYYY *(EPGL)*
> *"Date format still needs to be the other way round for example 14-02-2027"*

**Do** — check all four places a date appears:
1. **In chat:** `/embed/epgl-dialog` → renew a license; any expiry date in the reply.
2. **Application panel** (right side): any captured date row.
3. **Pencil edit:** click ✎ on a date in the panel — the editor shows the same format.
4. **Receipt:** open a completed payment's receipt link.

**Expect** `14-02-2027` everywhere. Never `2027-02-14`, `14 Feb 2027`,
`02/14/2027`, or a raw timestamp with `T00:00:00`.

**Ready-made receipt to check** (no journey needed):
<https://7xagents.7x-lab.com/api/receipt/PAY-9015?c=8bec7af4-8e23-4ca0-886b-31191d58f717>
→ Date should read **29-07-2026**.

### FB-1426 / FB-1407 — Confirmation email *(NXN)* — **BLOCKED, expected to fail**
> *"Requires Resend API Integration in order to send the emails"*

**Do** finish any paid journey and ask *"can you email me the receipt?"*

**Expect (this is the pass condition):** the assistant says plainly that it could
**not** send the email and offers the receipt **download link** instead.

**Fail looks like** the assistant claiming an email was sent. That is the actual
defect from the last round and it must not happen.

**To make it genuinely work:** add `RESEND_API_KEY` on Railway **and** set
`EMAIL_FROM` to a verified sender domain. `EMAIL_FROM` is currently Resend's
sandbox address, which only delivers to the Resend account owner — a key alone
will not fix it.

## B. Bugs fixed this round

### FB-1485 — Signed in with UAE PASS, then asked to sign in again *(NXN)*

This had **four** causes, so please test all four.

**1 — the main one (backend calls after sign-in)**
- `/embed/nxn-dialog` → sign in with UAE PASS (the ⇥ icon in the header), then ask
  *"show me my account"* and start a renewal.
- **Expect:** the conversation continues normally. **You are never asked to sign in
  again, told your session expired, or sent a one-time passcode.**
- If a backend detail genuinely cannot be fetched, the assistant should say that
  detail is unavailable and carry on — not bounce you back to sign-in.

**2 — the header chip**
- After signing in, **click the signed-in icon** in the header.
- **Expect:** nothing happens; it is a status indicator.
- **Fail:** it flips back to "Sign in" (that was the old behaviour and it looked
  exactly like being logged out).

**3 — a long signed-in conversation**
- Stay signed in and run a full journey through to payment.
- **Expect:** signed-in state persists to the end.

**4 — guests are unaffected**
- In a fresh session **without** signing in, try to rent a PO Box.
- **Expect:** you *are* asked to sign in — that gate still works. Only
  already-verified customers are never re-asked.

### FB-1393 / FB-1435 — Noticeable delay, hanging, inconsistent response time

**Do** complete a submission that includes uploaded documents (EPGL new license is
the best case), and watch the moment the final confirmation finishes printing.

**Expect** the "thinking" indicator stops and the input box is usable **as soon as
the reply is complete**.

**Fail looks like** the reply being fully visible but the chat still showing as
busy for several more seconds.

**Why:** the ops emails and the per-document Salesforce uploads used to hold the
connection open. They now run after the response is delivered — so the customer
stops waiting, while the back-office work still happens (check the admin
**Activity** page for `ops_notified` / `sf_document_attached` entries).

## C. Features added this round

### FB-1508 — Import a document into the knowledge base *(admin)*

**Do**
1. <https://7xagents.7x-lab.com/admin> → open an agent → **Knowledge** tab.
2. Click **Import document** and pick a PDF (a scan or an Arabic page is a good test).
3. Wait — a long PDF takes a few seconds while it is read.

**Expect** a green confirmation naming the document, the number of chunks and the
character count; the document then appears in the list and is published.
Title/source default to the file name unless you filled them in.

**Also test the refusals**
- A `.docx` → clear message asking you to export it as a PDF.
- A `.zip` or similar → "Unsupported file type".
- A blank file → "That file is empty."

**Then prove it is actually being used:** ask the agent a question that only that
document answers, and check the reply cites it (the **Sources** line).

## D. Items where the honest behaviour changed (backend cannot support the ask)

These will *not* do what the original feedback asked. The pass condition is that
the assistant is now **honest** instead of pretending.

### FB-1405 — GSB link not integrated *(NXN)*
**Do** `/embed/nxn-dialog?mock=1` → rent a **corporate** PO Box → reach the trade
license step.
**Expect** the assistant asks for the issuing entity and then asks you to **upload
the trade license**, explaining that documents are validated by the team.
**Fail looks like** any claim that it "verified", "matched" or "checked" your
Emirates ID against the company owner — there is no GSB integration to do that.

### FB-1404 — Save card / auto-renewal *(NXN)*
**Do** any renewal → at payment, switch on **Save my card** and **Enable auto-renewal**.
**Expect** the consent is recorded and the assistant says the request has been
submitted with the application.
**Fail looks like** "auto-renewal is now active" or "your card has been saved" —
the Emirates Post activation endpoint is disabled, so that would be untrue.

### FB-1403 — Bundle features *(NXN)*
**Do** ask *"what's included in the MyHome bundle?"*
**Expect** bundle **names and prices** from the live system, and features only if
the knowledge base has them — otherwise the assistant offers to confirm rather
than describing them.
**Still needed from NXN:** the correct feature list per bundle, so it can be
loaded into the knowledge base (you can now do this yourself via FB-1508 above).

### FB-1327 — EPGL payment gateway *(EPGL)*
**Do** submit an EPGL application, then later ask *"what's the status?"*
**Expect** the assistant reports the review status, and **once Salesforce has
issued the license it shows the licence number in the chat**. It explains that
EPGL issues the payment request after review, through EPGL's own channel.
**Fail looks like** the assistant offering to take payment in the chat or
producing a payment link — the Salesforce contract has no payment operation.

### FB-1268 / FB-1269 — Prefill from company profile / IDEP *(EPGL)*
**Do** sign in and start a renewal as a customer who has applied before.
**Expect** company details, Emirates ID and quarterly figures are pre-filled and
you are asked only to confirm them.
**Known limitation:** this is reconstructed from that customer's **previous
applications** — Salesforce/IDEP expose no company-profile read endpoint, so a
brand-new customer still goes documents-first.

### FB-1408 / FB-1409 — Proactive reminders / predicting needs *(NXN)*
**Do** sign in with `?mock=1` (the mock persona has boxes on file, one expiring).
**Expect** an **Account Pulse** on sign-in that flags what needs attention without
being asked, and a single next-best-action button after a completed request.
**Not built:** scheduled outbound reminders (email/SMS before expiry) — needs a
channel and consent decision.
